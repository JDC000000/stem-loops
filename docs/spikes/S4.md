# S4 — Decision Record: Key-Detection Library (librosa vs essentia)

- **Spike:** TSD §8 / S4 · Component C3 · per PRD §7.4 (BPM via librosa either way)
- **Success criterion (Gate 0):** pick the library with acceptable key accuracy **without** bloating the worker image / breaking cold-start budget; confirm `keys→piano` is musically acceptable or note the limitation.
- **Date run:** 2026-06-30 · **Status:** ✅ measured; recommendation = librosa.

## Footprint (MEASURED / verified)
| Library | Marginal cost in worker image | Notes |
|---|---|---|
| **librosa** | **~0 MB** | already a worker dependency for BPM; key via Krumhansl-Schmuckler on its chroma |
| **essentia** | wheel ~14 MB → **~40–50 MB installed** | + version fragility (below); not installed in this venv |

**essentia version fragility (real blocker):** the PRD/TSD-referenced pin `essentia==2.1b6.dev1110` **has no Python 3.12 build** — pip offers only scattered dev builds (`…dev1389` etc.). essentia means pinning a platform-specific dev build and re-checking it on every Python/OS bump; librosa ships stable releases.

## Key accuracy (MEASURED on synthetic samples — `s4_results.json`)
| Sample | Intended | librosa detected | Note |
|---|---|---|---|
| labeled_song | (multi-section, no single key) | C major | reasonable — track contains C-E-G material |
| neosoul_keys | **A minor** | **C major** | pitch-class correct; picked the **relative major** |

⚠️ This reproduces the **known librosa weakness** (PRD §7: "BPM good, key weak"): chroma-only Krumhansl-Schmuckler nails the pitch-class set but is weak at major/minor (relative-key) discrimination. Measured on **synthetic** pure-tone chords that are deliberately tonally ambiguous — not a verdict on real audio. Operator should confirm on a real neo-soul/lo-fi track.

## keys→piano mapping
htdemucs_6s emits a `piano` stem for what the PRD calls `keys`; the contract maps **piano → keys** in the UI/DB. The Rhodes/synth check ran on the synthetic neo-soul progression; the pitch content was captured correctly, the mode label was the relative major (see weakness above).

## Developer recommendation
**librosa.** Zero footprint, stable releases, adequate for the bedroom-producer use case. The relative-major/minor weakness is a known, bounded limitation — surface key as informational and, if real-track accuracy proves insufficient, revisit essentia (`2.1b6.dev1389`) or a dedicated key model as a *targeted* upgrade. Don't pay the footprint/fragility cost up front (YAGNI).
