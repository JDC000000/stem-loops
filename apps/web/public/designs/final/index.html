Section 03

Key design decisions in Phase 3b

Decisions locked in this phase. Items marked LOCKED cannot be reversed without a design review.

▸
Waveform as hero element
Accent color fills the played portion of waveform bars. Pre-computed peaks (no live analysis on load). Section markers at arrangement boundaries. Heights: 64px mobile / 80px desktop.
Locked
T
Typography system
System sans (no custom font load) for all UI text. Monospace for technical values only: BPM, job IDs, file names, hex codes. Scale: 32px hero → 11px micro-label.
Locked
■
Dark mode foundation
bg-page #0d0d0d → bg-nav #0a0a0a → bg-card #161616 → bg-elevated #1e1e1e. No pure black. Borders preferred over shadows. Four-level depth system.
Locked
⬤
Status color system
Soft palette — never saturated: Done #4ade80, Processing #60a5fa, Failed #f87171, Expiry warning #fb923c. Each has an 8% opacity background variant for status areas.
Locked
⇓
Mobile sticky ZIP CTA
On Results mobile, the Download All ZIP button docks to the bottom of the viewport in a 64px bar. Lifts above iOS home indicator. Q3 decision — accepted.
Q3 Decision
♬
'Keys' stem label — never 'Piano'
The keyboard/harmonic stem is always labeled "Keys" in all UI copy, filenames, and API responses. WAV filename format enforces this: *_keys_*.wav. Q2 decision — final.
Q2 Decision
⊕
Touch targets ≥44px
Every interactive element on mobile meets the 44px minimum touch target. Enforced via --touch-min token. Buttons, chips, links, drag handles — all verified. No exceptions.
Locked
⇔
WAV filename format
Standardized pattern: {title}_{stem}_{bpm}bpm_{key}_{section}_{idx}.wav. Applied consistently across Results screen, History, and API responses.
Locked
△
Three accent options presented
Design tokens ship with all three accent definitions. A single body class swap activates any option. No CSS changes needed in component files after the operator picks.
Pending operator pick
