Phase 3b · Error States

Error States

All 9 error codes rendered in their inline card format. Each error surfaces contextually within the flow — never on a dedicated error page. Users see these in-place where the failure occurred (submit form, progress screen, or results view) with a clear action to recover.

No stack traces rule: Error messages are plain English only. Technical codes (e.g. DOWNLOAD_BLOCKED) appear as micro-labels for debugging context but are never the primary message. Server-side errors log internally; nothing is surfaced to the user beyond a single reassuring sentence.

Download errors
5 / 9

DOWNLOAD_INVALID_URL

Invalid URL

User-facing message

Paste a full youtube.com or youtu.be URL.

What to do next

Check the URL starts with https:// and includes a video ID. Playlist or channel links won't work — link directly to a video.

DOWNLOAD_BLOCKED

Access Blocked

User-facing message

YouTube is temporarily blocking automated access. Try again in a few minutes.

What to do next

This is a transient rate limit on YouTube's side. Wait 2–5 minutes then retry. The video itself is accessible — it's just a temporary hold.

DOWNLOAD_TIMEOUT

Download Timed Out

User-facing message

We couldn't reach that video in time. Check the link and try again.

What to do next

The download took longer than 30 seconds — usually a network blip. Confirm the video still plays on YouTube, then retry. Very long videos (60+ min) may not be supported.

DOWNLOAD_AGE_RESTRICTED

Age-Restricted Video

User-facing message

This video is age-restricted and can't be processed.

What to do next

Age-restricted videos require YouTube sign-in to access — our system can't authenticate with YouTube. Try a different upload or find an unrestricted version of the track.

DOWNLOAD_PRIVATE

Private or Unavailable

User-facing message

This video is private or unavailable.

What to do next

The video may have been removed, set to private, or the URL may be broken. Open the link in your browser to verify it's still public, then try again.

Processing errors
3 / 9

SEPARATION_FAILED

Stem Separation Failed

User-facing message

Stem separation failed for this track. Try a different song.

What to do next

Our AI couldn't isolate stems for this audio — likely due to heavy compression, very low quality, or an unusual audio format. Submit a different track to continue.

EXTRACTION_FAILED

No Loops Found

User-facing message

Couldn't find clean loops (audio may be too short or beatless).

What to do next

Loop extraction works best on tracks with a clear rhythmic pattern (drums, bass, keys). Very short clips or ambient/spoken-word audio won't yield usable loops. Try a full-length instrumental or vocal track.

UPLOAD_FAILED

Save Failed

User-facing message

We separated your stems but couldn't save them. Please retry.

What to do next

The separation succeeded but the final upload to storage failed. Retrying re-uses the already-processed audio — no re-processing needed. Usually resolves immediately.

Catch-all
1 / 9

INTERNAL_ERROR

Internal Server Error

User-facing message

Something went wrong on our end. We've logged it — please try again.

Server-side only logging: The error is captured in our backend log with a trace ID. No stack trace, error code, or technical detail is ever surfaced in the UI. The phrase "We've logged it" is the only signal to the user that we're aware of the issue.

What to do next

Retrying usually resolves transient infrastructure errors. If the problem persists across multiple attempts, the user should try again in a few minutes while our systems self-heal.

Design notes

Inline placement, not a dedicated page

All 9 error states render inline at the point of failure. Download errors appear inside the submit form card. Processing errors replace the progress indicator in the progress screen. Upload failures surface in the results view. There is no standalone error route — the user never leaves their context.

No stack traces rule

Error messages are constrained to plain English sentences. The error code (e.g. DOWNLOAD_BLOCKED) is displayed as a 10px uppercase micro-label for internal debugging reference only — it is never the primary communication. Stack traces, exception messages, and HTTP status codes are never shown in the UI under any circumstances.

CTA logic per error type

Recoverable errors (BLOCKED, TIMEOUT, UPLOAD_FAILED) show a primary accent-colored Retry button. Non-recoverable errors (AGE_RESTRICTED, PRIVATE, SEPARATION_FAILED, EXTRACTION_FAILED) skip the retry CTA and offer only a ghost "Try Different URL/Song" button. INTERNAL_ERROR always shows a retry. DOWNLOAD_INVALID_URL shows a "Fix URL" action that refocuses the input.
