Key Design Decisions Made in Phase 3a
Aesthetic direction (dark-mode audio tool)
  • Background #111–#161616 (not pure black — matches DAW UI greys like Ableton Live)
  • Zero decorative imagery. Every pixel serves a function.
  • Waveform is the hero element on Results — larger than any other visual
  • Minimal chrome: no sidebar navigation, no modal overlays in V2
  • Greyscale wireframes communicate dark-mode-first intent clearly
Submit screen: form-is-the-product
  • URL input is the largest touch target on mobile — immediate focus
  • Stems use 2-col chip grid (mobile) / 3-col (desktop) for comfortable selection
  • Loop length: 4-up segmented selector across full width (mobile) — tactile
  • Submit CTA disabled until valid URL + ≥1 stem (zod validation)
  • Recent jobs strip on desktop (below form) — conditional on localStorage
  • No marketing copy beyond one-line tagline — users know what stems are
Progress screen: real-time feel without WebSocket
  • Polling GET /api/jobs/:id every 2s — sufficient for V2 scale
  • Share URL exposed immediately (before job completes) — share early
  • Desktop: sidebar (stage list) + large content (current stage viz) — two densities
  • Stage pip strip (6 dots): compact "where in pipeline" visual shorthand
  • Timing cards: elapsed / ~remaining / stages done. Remaining is approximate.
  • Auto-navigate to results when status = done
Results screen: waveform-first, audition-before-download
  • Waveform renders from pre-computed peaks (loops.waveform_peaks) — no client decode
  • Play button left of waveform — tap to audition BEFORE downloading
  • Section markers: thin vertical overlays on waveform at section boundaries
  • 5 tags per loop: stem (prominent) / BPM / key / section / energy
  • Drag handle: HTML5 draggable → DAW accepts as .wav (PRD §4.4)
  • Desktop 2-col grid; mobile single-column. Both scrollable (no pagination)
Error states: actionable, no dead ends, no stack traces
  • All 9 TSD §6.2 errors have distinct cards: icon / code label / plain message / next steps / CTA
  • INTERNAL_ERROR: deliberately vague to user. Always logged server-side.
  • Error cards appear inline on Progress screen (not a separate error page)
  • "Retry" → re-queues same URL. "Try different URL" → Submit screen, cleared.
  • DOWNLOAD_INVALID_URL shown inline below URL input on Submit (not progress page)
Job history: anonymous, persistent, mobile-first
  • localStorage primary + signed cookie secondary (cross-tab persistence)
  • No account — fulfills PRD §4.4 "anonymous job history"
  • Mobile: card list with color status stripe. Desktop: table with filter/search.
  • Expiry warning: <24h shows red date text + advisory note → download now
  • Failed jobs show user-friendly error reason, not raw error code
  • Processing jobs link to progress screen (jobs started on phone, finish on desktop)
Questions for operator before Phase 3b
Q1
Results screen: 2-column card grid vs 1-column full-width cards on desktop. The 2-column grid lets producers scan more loops at once, but each card is narrower (waveform height is limited). Preference?
Current decision: 2-col grid on desktop (≥1440px), 1-col on mobile. A "wide" 1-col layout could make waveforms more readable at the cost of vertical scroll.
Q2
Stem labels: the TSD confirms htdemucs_6s uses "piano" not "keys". The wireframes use "Piano" consistently. Is that the final label, or do you want to display "Keys" in the UI while mapping to "piano" internally?
TSD §C5 says "Map keys → piano in the contract and UI labels." Current decision: show "Piano" in UI. Confirm or override.
Q3
Should the mobile Results screen have a fixed bottom bar with "Download ZIP" so the CTA is always visible while scrolling through loops?
Current decision: ZIP CTA is at the top of the loop list (scrolls away). A fixed bottom bar adds chrome but keeps the most valuable action always reachable.
Q4
The Progress screen on desktop shows a "Cancel job" button in the sidebar. Should cancel be a destructive confirmation (modal) or instant with an undo window?
Current wireframe shows a simple button. No modal shown. For V2 simplicity, instant cancel seems right — but confirm intent.
Q5
Phase 3b color direction: the PRD says "dark-mode first, audio-tool aesthetic (Ableton/Splice/Bandcamp dark)." Any specific accent color in mind (Splice uses hot orange, Ableton uses a warm yellow)? Or should Phase 3b propose 2–3 accent options for your choice?
Phase 3b will generate design-tokens.css. The accent color drives CTA buttons, active states, waveform playhead, and highlighted tags. A stem-loops brand color is needed.
